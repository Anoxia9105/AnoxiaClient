# Implementation Plan: 日程 V2

## Overview

以兼容性优先的方式扩展日程数据契约，随后用自研日历视图替换当前第三方 UI，最后接入提醒调度并完成跨语言、响应式和发布验证。每个阶段保持客户端与服务端可编译、可回滚。

## Architecture Decisions

- REST 路径不变，只新增可选字段，旧客户端继续可用。
- 重复规则按系列保存，实例在客户端按查询窗口展开，不预生成无限记录。
- 日/周/月核心 UI 自研，移除 `calendar_view` 对交互和语言的控制。
- 通知复用现有 `NotificationHelper`，Web 权限只由用户操作触发。

## Risks and Mitigations

| 风险 | 影响 | 缓解 |
|---|---|---|
| 拖拽与滚动手势冲突 | 高 | 只从事件块和调整手柄启动，设置移动阈值并写组件测试 |
| 重复规则无限展开 | 高 | 始终限制在查询窗口，限制 count/interval |
| Web 后台提醒能力有限 | 中 | UI 明示“应用打开时提醒”，后续以 Web Push 扩展 |
| 乐观更新失败造成视觉错乱 | 高 | 保存前保留快照，失败原子回滚并刷新服务端状态 |
| 自研布局引入重叠问题 | 中 | 事件分列算法使用纯函数并覆盖重叠测试 |

## Confirmed Scope

- 第一版重复日程只编辑整个系列，Web 提醒只保证应用打开时触发。
