# 日程 V2 规格

> 实施状态：2026-09-22 已完成。重复实例第一版按整个系列编辑/删除；Web 通知仅保证应用打开时触发。

## 目标

把“我的日程”升级为适合 Web PC 与 Windows 桌面端长期使用的个人日历：信息层级清楚、时间轴易读、交互有反馈，并支持提醒、拖拽改期/改时长、自定义颜色和基础重复日程。

## 本期范围

### 1. 全新日历 UI

- 重写日、周、月、议程视图，不再由 `calendar_view` 控制核心布局与交互。
- 顶部工具栏包含：今天、前后周期、当前日期范围、日/周/月/议程切换、新建日程。
- 日/周时间轴使用固定宽度时间栏、整点主刻度、半小时次刻度、当前时间线和全天区域。
- 日程块显示颜色、标题、时间；空间足够时显示地点和重复/提醒图标。
- 月视图固定为六行网格，显示溢出数量；议程按日期分组。
- 支持亮色/暗色主题、键盘焦点、空状态、加载骨架、错误重试和窄窗口降级。

### 2. 完整国际化

- 所有星期、月份、日期范围、时间、全天、溢出数量和交互提示均使用当前应用 locale。
- 首批支持中文、英文、日文，禁止在日历 UI 中硬编码英文星期或月份。
- 星期从周一开始；日期和时间格式遵循 locale。

### 3. 拖拽与调整时长

- 日/周视图支持拖动普通日程改变日期和开始时间。
- 日程底部提供可见的调整手柄，拖动改变结束时间。
- 移动和调整均按 15 分钟吸附，最短时长 15 分钟。
- 保存期间显示进行中状态；失败时回滚原位置并给出可重试提示。
- 全天日程和重复日程第一阶段通过编辑器修改，不直接拖动，避免产生含糊的系列修改。

### 4. 自定义颜色

- 编辑器提供一组无障碍对比合格的预设色，并保留自定义十六进制颜色输入。
- 颜色不仅用于侧边条，也用于日程块背景/边框；当前选中颜色有文字或勾选标识，不能只靠颜色表达。

### 5. 重复日程

- 支持不重复、每天、每周、每月。
- 支持间隔、每周的星期选择，以及永不结束、指定日期结束、指定次数结束。
- 第一阶段编辑和删除作用于整个系列；UI 必须明确显示“编辑整个系列”。
- 服务端保存系列规则，客户端只展开当前查询窗口内的实例，避免无限生成记录。

### 6. 到期提醒和桌面通知

- 每个日程支持一个提醒：开始时、提前 5/10/15/30 分钟、1 小时、1 天或关闭。
- 复用现有 `NotificationHelper`；权限只能由用户按钮主动申请。
- Web 第一阶段在应用处于打开状态时可靠触发系统通知；浏览器关闭后的后台推送不在本期承诺范围。
- Windows/macOS/Linux 使用现有本地通知能力；启动、编辑和删除后重新计算待提醒项，避免重复提醒。

## 数据与 API 契约

现有 REST 路径保持不变，写模型和返回模型只增加可选字段，兼容旧客户端：

```json
{
  "reminderMinutes": 15,
  "recurrence": {
    "frequency": "WEEKLY",
    "interval": 1,
    "weekdays": [1, 3, 5],
    "endType": "UNTIL",
    "until": "2027-01-31T23:59:59.999Z",
    "count": null
  }
}
```

- `weekdays` 使用 ISO weekday：1=周一，7=周日。
- `frequency`：`DAILY | WEEKLY | MONTHLY`；不重复时 `recurrence=null`。
- `interval` 范围 1..99，`count` 范围 1..999。
- 服务端继续校验资源归属、时间范围、颜色和乐观锁版本。

## 测试策略

- Dart 单元测试：重复展开、跨月、闰年、月末、提醒时间、15 分钟吸附。
- Flutter 组件测试：国际化星期/月、颜色选择、提醒选择、拖动回滚、重复规则表单。
- Java 服务测试：新增字段校验、持久化、查询重复系列、旧请求兼容。
- 发布验证：`flutter analyze`、日程测试、Web release/Wasm dry-run、服务端 Maven 测试与编译。
- 浏览器人工路径：1440、1024、768 宽度；中文/英文/日文；日/周/月/议程；拖动、缩放、提醒授权。

## 边界

- 始终：数据库变更提供增量 SQL；所有写入保留乐观锁；拖拽失败必须回滚；新增文本完整翻译。
- 本期不做：共享日历、参与人、Google/Outlook 同步、ICS、单次重复实例例外、浏览器关闭后的 Web Push。
- 不允许：为实现拖拽修改第三方 Pub 缓存；静默申请通知权限；一次性预生成无限重复实例。

## 验收标准

- 四种视图均无硬编码英文日期文本，切换 zh/en/ja 立即正确显示。
- 日/周时间栏在 100% 与 125% 缩放下仍清晰，拖动/缩放准确吸附且失败可恢复。
- 新建、编辑、删除、颜色、提醒和重复规则可跨设备持久化。
- 页面无运行时异常，日程相关测试、静态分析、Web 发布构建和服务端测试全部通过。

## 待确认假设

- 已确认：第一版重复日程只支持“编辑/删除整个系列”。
- 已确认：Web 桌面通知第一版只保证应用打开时触发；真正关闭浏览器后的提醒需要后续 Web Push 服务。

## 实施与验证记录

- 客户端已移除 `calendar_view`，月视图不再经过其泛型运行时边界。
- 月视图使用周一开头的固定 6×7 网格；日/周视图采用 72px 时间栏、半小时网格、当前时间线、全天区与重叠事件分列。
- 普通非重复日程支持 15 分钟吸附的长按拖动和底部手柄调时长；服务端写入失败时恢复原状态。
- 提醒由页面在加载、创建、编辑和删除后重新计算；通知权限只能由工具栏按钮主动申请。
- 自动化验证覆盖 768/1024/1440 宽度、zh/en/ja 日期格式、重复边界、提醒时间、重叠布局和乐观回滚。
- `flutter build web --release`（含 Wasm dry-run）通过；浏览器 release 启动与控制台检查通过。受登录保护且无测试账号，浏览器内未执行鉴权后的数据写入。

## 基础接口与部署

所有接口要求登录，资源归属由服务端认证上下文确定：

```text
GET    /schedule/events?from=<RFC3339>&to=<RFC3339>
GET    /schedule/events/{id}
POST   /schedule/events
PUT    /schedule/events/{id}
DELETE /schedule/events/{id}
```

更新携带最近读取到的 `revision`；版本冲突时刷新后重试。普通日程使用 UTC 瞬时值，全天日程使用 UTC 零点承载日期边界。重复系列由客户端按查询窗口展开。

新环境使用服务端 `anoxia.sql`。已有环境核对 `2026-09-22-schedule-event.sql` 与 `2026-09-22-schedule-event-v2.sql`，按数据库现状执行所需迁移。
