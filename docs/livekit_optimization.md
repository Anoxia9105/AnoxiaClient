# 通话优化范围与验收

目标：更稳定、更快接通、更易用。保留 adaptiveStream、Dynacast、SDK 默认 Simulcast 和挂断资源屏障。

## 实施范围

1. 麦克风优先初始化，摄像头故障独立处理；监听先于连接；最终断连转为可重试状态。
2. 异步媒体操作合并最新状态，关闭期间禁止回写；共享失败/系统停止后回收资源。
3. 共享档位：清晰 1080p/15 FPS、流畅 1080p/30 FPS、低带宽 720p/15 FPS。采集与发送上限一致。
4. 浏览器支持时发布共享音频轨，音视频一起停止；切换共享源先完成原共享清理。
5. 摄像头档位与摄像头/共享独立编码偏好，探测发送能力，保留兼容回退；默认不强制 AV1。
6. 振铃时仅预热 DNS/TLS，不提前连接房间或采集设备；连接时复用预热结果。
7. 质量估算使用采样差值，集中收集本次通话的实时诊断数据。
8. 通话设置、共享与诊断入口覆盖桌面和移动布局，中英日文案齐全。

## 验收

- 回归：设备失败隔离、清除错误、关闭屏障、采样重置/恢复、编码回退、帧率一致。
- 构建：flutter analyze、flutter test、Web 编译。
- 真机矩阵：Windows/浏览器双端，反复开关摄像头与共享、标签页声音、共享窗口消失、退出时切设备、断网恢复、VPN/企业网络。
- 性能对比：接通/首帧耗时、FPS、码率、RTT、丢包、CPU 限制原因。未取得双端数据前，不声称编码器带来确定性能收益。

## 外部条件

服务端 UDP/TCP/TURN/TLS 的实际监听、防火墙与证书需部署环境验证。iOS 跨 App 共享需 Broadcast Extension、App Group 与 Apple 签名能力，Windows 无法完成 Xcode 签名和真机验收。

## 使用与部署

通话控制条的设置菜单提供画质、独立编码偏好和诊断。摄像头设置立即重建已开启的摄像头轨道，共享设置在下次开始或切换源时生效。浏览器共享声音需要在系统选择器中选择允许声音的标签页/共享源；原生共享声音暂不提供开关。iOS 当前只共享本 App，启动后显示范围提示。

编码能力探测只证明可请求该编码，不证明硬件加速。自动模式在原生移动端优先请求 H.264，其他平台优先 VP8；显式设置不支持的编码会回退到可用编码，SDK 保留默认备用编码策略。编码运行失败会提示失败，不声称可以无缝恢复所有驱动故障。

部署端应检查：公开信令 WSS 与可信证书、客户端可达的媒体公网 IP、部署所选 UDP 端口范围或 UDP mux、ICE/TCP 回退、TURN/UDP 与 TURN/TLS。通过企业网络和禁用 UDP 的双端实测确认回退路径；仅 HTTP/TCP 可达不能证明媒体可达。参考 [LiveKit 部署说明](https://docs.livekit.io/transport/self-hosting/deployment/)、[屏幕共享说明](https://docs.livekit.io/transport/media/screenshare/) 与 [媒体高级选项](https://docs.livekit.io/transport/media/advanced/)。

## 通话恢复与群成员退出

- SDK 恢复耗尽后，网络/媒体类断线额外尝试有限次恢复；终止类原因不恢复，挂断或销毁取消计时器，并保留用户的麦克风和摄像头意图。
- 恢复前台重新查询群通话状态，开始/结束事件优先于旧 HTTP 响应。
- 群成员普通退出只释放本端媒体，不广播结束整个群通话；私聊挂断发送对应信令。群会议结束以实际房间结束状态为准。
- 展示名称使用会话标题，不使用 LiveKit 的房间 ID。诊断按真实统计采样计算码率与 FPS，不将设置上限当作实测结果。
- 移动端共享画面支持横屏查看与缩放。媒体上传的转码和配额约定见服务端 `docs/FFMPEG-DEPLOYMENT.md`；旧视频不会自动迁移。
