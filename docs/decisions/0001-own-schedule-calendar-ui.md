# ADR-0001: 自研日程日历交互层

## Status

Accepted

## Date

2026-09-22

## Context

当前日程 UI 使用 `calendar_view: 2.0.0`。该版本曾因月视图泛型擦除导致 Web 发布构建运行时崩溃；它的日期语言需要额外同步，并且没有事件拖动改期或拖动边缘调整时长的正式接口。继续在事件 builder 上叠加手势会让滚动、拖拽和回滚状态相互耦合。

## Decision

在日程功能内部实现可控的日、周、月和议程视图，并把日期格式、事件布局、吸附和拖拽写回拆为可测试的纯逻辑。完成替换后移除 `calendar_view` 依赖。

## Alternatives Considered

### 继续包装 calendar_view

- 优点：初始改动较少。
- 缺点：拖拽/缩放没有稳定扩展点，语言与泛型问题仍受第三方实现约束。
- 结论：不采用。

### Fork calendar_view

- 优点：可复用已有布局。
- 缺点：需要长期维护整套第三方组件，升级和 Web/Windows 回归成本较高。
- 结论：当前功能范围下不采用。

## Consequences

- 获得稳定的拖拽、缩放、国际化和视觉控制权。
- 需要自行维护事件重叠布局、滚动同步和月网格算法，因此这些逻辑必须有独立测试。
- 初次重构成本较高，但可删除已出现运行时缺陷且无法满足交互目标的依赖。
